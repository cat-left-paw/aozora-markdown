## Generated mappings

`scripts/generate_data.py` executes the hash-pinned original `jis0213_to_unicode` under CPython **3.12.8**. All 17,672 plane/row/cell results are generated from `euc_jis_2004`, including 372 nulls, 25 multiple-codepoint results and the codec's JIS X 0212 fallback. CP932 and Shift_JIS tables are independently generated from those two named CPython codecs. Unicode decimal values come from that runtime's Unicode 15.0 database. No standards table or browser TextDecoder label replaces these runtime results.

`data-provenance.json` records the source hash, generator hash, data hashes, byte sizes and verification population. `python3 scripts/generate_data.py --check` regenerates in memory and compares exact bytes without changing files.

Upstream lineage inspected on 2026-09-22:

- [CPython v3.12.8 Japanese mapping generator](https://github.com/python/cpython/blob/v3.12.8/Tools/unicode/genmap_japanese.py): names JIS0208, JIS0212, CP932, JIS X 0213 input tables and the fullwidth mapping patch requirement.
- [CPython Japanese codec](https://github.com/python/cpython/blob/v3.12.8/Modules/cjkcodecs/_codecs_jp.c) and [generated Japanese mappings](https://github.com/python/cpython/blob/v3.12.8/Modules/cjkcodecs/mappings_jp.h).
- [CPython license](https://github.com/python/cpython/blob/v3.12.8/LICENSE): full upstream text in `CPython-LICENSE.txt` (PSF and historical notices).
- [Unicode mapping CP932](https://www.unicode.org/Public/MAPPINGS/VENDORS/MICSFT/WINDOWS/CP932.TXT): source header preserved in `CP932-source-header.txt`; [Unicode data license](https://www.unicode.org/license.txt) copied as `Unicode-MAPPINGS.txt`.
- [Project X0213 mapping](https://x0213.org/codetable/jisx0213-2004-std.txt): copyright and permission header copied as `JIS-X0213.txt`. The table grants use, modification and distribution. It is a provenance reference, not the generated runtime table used here.

The CPython generator still contains an old infoseek table URL. The live Project X0213 notice is included alongside CPython and Unicode notices; the generated values remain pinned to CPython 3.12.8, not a refreshed table. The project's MIT license does not replace these third-party licenses and notices.

## Dependencies

Runtime dependency: `yaml` **2.9.1**, ISC, copyright Eemeli Aro. Full notice is `yaml-LICENSE.txt`. It is bundled in the main browser ESM; the encoding and policy entries do not depend on YAML.

Build/test tools are exact-version locked in `package-lock.json`. `reports/dependencies.json` records their versions and licenses, including transitive packages. They are not imported by runtime entries. `dist/notices/` receives these notice files on build.

ZIP import uses `@zip.js/zip.js` **2.17.0** (BSD-3-Clause), exactly pinned in the lockfile; full license: `zip.js-LICENSE.txt`. The bundled `lib/zip-core-native.js` entry includes a JavaScript zlib codec. `useWebWorkers:false` and `useCompressionStream:false` select that bundled codec without a nested Worker, WASM, CDN, or native-codec fallback. STORE/DEFLATE are the supported import methods.

The packaged codec README points to [zlib-streams-ts](https://github.com/gildas-lormeau/zlib-streams-ts). Its README says BSD/zlib, while the actual linked LICENSE.md contains MIT permission and credits Gildas Lormeau and the original zlib authors. `zlib-streams-ts-LICENSE.txt` preserves that file verbatim, including both copyright lines. `zip-provenance.json` records its immutable source URL, license hash, and the hash of the codec actually bundled from the pinned npm package; the two code snapshots are not asserted to be identical.

ZIP filename CP437 values are generated independently from CPython 3.12.8 by `scripts/generate_zip_fixtures.py`; the 256-value table is checked by `npm run zip:check`. The existing CPython license applies. ZIP fixture production uses only Python zipfile/struct/zlib; manifest hashes and purposes live in `tests/fixtures/zip/manifest.json`. No old oracle fixture is regenerated by this script.

`zip.js-source-notices.txt` also retains the distinct copyright/license/JZlib attribution comment blocks from the zip.js modules in the actual import bundle's esbuild input graph. Its hash is recorded in `zip-provenance.json`.

ZIP export uses the same exact **2.17.0** package and `lib/zip-core-native.js` entry for STORE-only output. `zip-provenance.json` adds the installed writer source hash and `aozora-export-v1` profile. The export bundle's 38 zip.js input modules are a subset of the existing import input graph; writer/IO/CRC/stream/native registration notices are already retained verbatim. No dependency upgrade or new third-party license text is needed. Existing license/source notice bytes are unchanged. The bundle includes native-entry codec registration, although STORE does not compress: the explicit no-inner-Worker/no-compression-stream settings require no auxiliary codec asset, WASM, CDN or fetch.

The preview Worker uses `markdown-it` **15.0.2** (MIT, copyright Vitaly Puzrin and Alex Kocharin), exactly pinned in `package.json` and the lockfile. It is bundled only in the Web app's dedicated preview Worker (`web-dist/preview.worker.js`); `main.js`, the library `dist/` entries and the existing 9 bundles do not import it. `reports/web-build.json` records the Worker's esbuild input graph under `previewWorker.inputs`, and `scripts/build-web.mjs` fails if the parser appears in the main graph or UI/adapter modules appear in the Worker graph. `scripts/export-library-probe.mjs` checks the pinned writer settings, UTC/Asia-Tokyo binary reproducibility and pre-retention chunk budget; `scripts/check_export_zip.py` independently checks emitted headers, central directory, EOCD, CRC, attributes, UTF-8 names, order and complete payloads using Python standard zipfile/struct/binascii. CPython is test-only; no runtime Python dependency is introduced. `reports/bundle-sizes.json` enumerates every entry's parsed source graph and size/hash, and the export runtime probe records all emitted JavaScript assets. Source maps, declarations, LICENSE and notices are copied/generated by build.
